# M54：点确认对话框里真实的按钮；对话框开着时 ⌘Q

状态：已完成。只改了应用内自检与 E2E（产品代码没有变化）。
关联 `m53-confirm-destructive-actions.md`、`m31`（sheet 打开时 terminate 被 AppKit 静默拒绝）。

## 1. 背景

M53 的「诚实边界」里留了三条：没有点对话框里的按钮（自检调的是它们绑定的函数）；对话框开着时按 ⌘Q 没有测试；Stop 的确认没有在真机流程里走过。其中第二条不是小事——这个项目最初的 bug 就是「有 sheet 时 ⌘Q 无效」，而 M53 新增的确认对话框正是一个 sheet。

## 2. 做法

- 自检里新增 `sheetButtons()` / `clickSheetButton(_:)`：在挂着的对话框里按标题找到 `NSButton` 并 `performClick`——走按钮自己的 target/action，与鼠标点击同一条路，**不需要辅助功能授权**。
- G10 的真机流程改为：Stop → 对话框出现 → 点「停止」→ stopped；Rm → 对话框出现（按钮是「取消」「移除」）→ 点「取消」→ 沙箱还在 → 再 Rm → 点「移除」→ 沙箱消失。
- 新场景 `DBX_GUI_SELFTEST_SCENARIO=confirm`（G14）：socket 上是记录请求的假 daemon；让「移除沙箱」的确认对话框开着，然后 ⌘Q。验证：发 ⌘Q 时对话框确实开着；App 经 terminate 路径退出；**假 daemon 自始至终只收到 `ps` / `info`**——退出没有顺手执行那个待确认的移除。

## 3. 验证

- `e2e-gui-app.sh` 85 项（新增 5）全部通过；`swift test` 472 全绿。
- 变异检查（先提交再变异，随后还原）：把「取消」按钮接到执行函数上 → G10「点取消后沙箱还在」失败（沙箱被移除了）。说明点击确实经过了视图里的按钮，而不是绕到模型上。
- 全量 `e2e-all.sh`：见证据文件。

## 4. 诚实边界

- `performClick` 不是鼠标事件：它不经过命中测试，按钮被别的视图挡住、或在屏幕之外时也会成功。它验证的是「按钮存在、可用、接到了正确的动作」。真正的鼠标 / 键盘事件（需要辅助功能授权）仍未测试。
- 对话框里的回车 / Esc 默认键没有测试。
- Restart 与 Shutdown Daemon 的确认仍只有单元测试；菜单栏弹窗 → 主窗口弹确认这条路仍未测试。
- 锁屏时沙箱停在 suspended，没有 Stop 可点，那一项记为锁屏跳过。
- G14 用的沙箱 id 是虚构的（对话框只需要一个 id）；如果退出真的误发了移除，假 daemon 会记录到 `rm`，但不会有真实沙箱受损——这是有意的。
