# M44：环境缺失的跳过也算「不完整」；终端的 `\r` 重绘；其余等待接入控制面丢失的即时失败

状态：已完成。本轮**没有改 guest**（候选不需要重建），也**没有碰 suspend / resume 路径**。
关联 `m36-e2e-evidence.md`、`m33-terminal-reopen-and-stats.md`、`m43-control-loss-and-broker-result.md`。

## 0. 为什么是这些

宿主仍然锁屏。M42 / M43 各有一处改动落在 resume 会经过的路径上，至今没有真机证据；在拿到证据之前不该再往那条路径上加东西。本轮挑的是三件互不相关、都不经过 resume、且都能在锁屏下完整验证的事。

## 1. 证据：环境缺失导致的跳过此前不影响结论

M36 的证据把「因锁屏跳过」记为不完整，其它跳过一概不管。M37 之后套件里出现了另一类跳过：没有交叉编译器时，`*-patched` 套件（guest 侧修复的全部验证）整套跳过；没有网络时真实下载跳过；缺 GPU 内核时 Display 跳过。这些情况下 `e2e-all.sh` 退出码仍是 0，证据的结论仍是「完整通过，可作为发布证据」。

现在跳过分三类（`scripts/lib/e2e-common.sh`）：

| 写法 | 含义 | 对结论的影响 |
| --- | --- | --- |
| `skip_locked` | 宿主锁屏 | 不完整 |
| `skip_na <what> <why>` | 这个模式下本来就不该做的检查（目前只有一处：隔离模式不检查 GUI 进程） | 无 |
| `skip` | 其它一切：缺工具、没网络、缺资产…… | **不完整**（新） |

默认是「算不完整」：新写的 `skip` 不加标记就不会被悄悄当成通过。

- `e2e-all.sh`：逐条列出「未验证（环境）」，结尾多一个计数；有这类跳过时退出码 3。
- `e2e-evidence.py`：套件新增 `envSkipped` / `notApplicable`；相关不变量标为不完整，未验证清单里以 `[环境]` 开头；发布阻断原因里单列。SKIP 计数多于有明细的条数时，差额按「没有说明原因的跳过」计入（宁可多报）。旧证据文件没有这两个字段，不被追溯改判。

## 2. 终端：`\r` 行内重绘

`TerminalTextFilter` 此前把 `\r` 直接丢弃：进度条 `10%\r20%\r30%` 显示成 `10%20%30%`，shell 的行编辑重绘会把旧内容和新内容拼在一起。

现在过滤器记录光标在当前行（最后一行）里的列：

- `\r` 回到行首，之后的可打印字符**覆盖**该列上已有的字符；写过行尾则转为追加；`\r\n` 不受影响；
- 重绘中的退格只移动光标（在行尾时仍是删掉前一个字符，shell 回显的 `\b \b` 照旧）；
- 解释 `ESC[K`（0 / 缺省：擦到行尾；2：擦整行）和 `ESC[J`（缺省 / 0，在最后一行上等同于擦到行尾——ash 的行编辑用它）。其余 CSI 序列照旧只是被移除；
- 与真实终端一致：更短的重绘如果不擦除，会留下旧内容的尾巴。

## 3. 控制面丢失：其余等待也立刻失败

M43 只给 exec 与 stats 的等待接入了 `DBX-GUEST-CONTROL-LOST`。本轮补上打开终端、终端轮询、workspace 同步。终端轮询的影响最直观：guest 的控制进程死掉之后，轮询此前会一直返回「还在运行、没有输出」，界面上就是一个永远不动的终端。

## 4. 顺手

`e2e-release-cli.sh` 自己做 `swift build`，重新链接会丢掉代码签名，随后带 `E2E_SKIP_BUILD=1` 运行的 VM 套件会因缺 entitlement 全部失败（M38 记录的隐患）。现在它在构建后检查并补签（`e2e_sign_if_needed`；没有签名身份的机器上不做任何事，CI 不受影响）。

## 5. 验证

`e2e-harness-selftest.sh`（52 项，新增 5）：环境跳过 → 不变量不完整、整体不完整、check 退出码 3；「不适用」不影响结论；SKIP 计数多于明细 → 差额计入；锁屏与环境同时存在 → 两个原因都列出；旧证据文件不被改判。

## 6. 诚实边界

- **resume 相关的 9 项断言仍未验证**，M42 / M43 留下的那两处风险没有变化。本轮只是没有再增加。
- 环境跳过的分类靠约定：套件作者用了 `skip_na` 就不计入。目前只有一处，理由写在调用点；没有机制阻止滥用。
- 「没有说明原因的跳过」只在新格式的证据里计算；本机这次运行里环境缺失的跳过为 0，所以这条路径的真机表现只有自检覆盖（用构造的证据）。
- 终端仍然不是终端模拟器：只有「最后一行」的概念，没有光标上移、没有屏幕缓冲。会上下移动光标的全屏程序（`top`、`vi`）显示仍然是乱的。`ESC[1K`（擦到行首）没有实现。
- 列按 Swift 的 `Character` 计：一个汉字算一列。真实终端里它占两列，所以「用 ASCII 覆盖汉字」这类混排重绘的对齐与真实终端不同。
- 终端的测试是应用内自检（模型层）和单元测试，不是真实窗口里的肉眼确认。
- 控制面丢失的即时失败在 `launch` 子命令走的几条等待上没有接入。
